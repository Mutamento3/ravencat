# 数据库基线与升级边界

## 当前契约

- schema 当前版本为 124，包含两级摘要、固定上下文起点、角色私有图片／表情、单聊 Token 显示配置、独立消息收藏和持久摘要任务／请求设置；旧迁移文件中的 114/115 是代码编号，已发布库实际保存 `PRAGMA user_version=108`。
- 新安装直接从当前 schema 建立表、索引、触发器和默认记录，不运行开源前的迁移链。
- 当前公开版升级补齐当前结构、清理没有有效主体的 MCP 授权并提交新版本标记；108／116 的旧触发词各自迁成单词组，保留 ID、动态文本关联、手动关系和关闭开关。正常聊天、记忆正文、向量、摘要、协议、朋友圈、授权和日程保持原样。
- 117 私有库直接原子升级摘要结构，原摘要标为一级，正文与处理游标不改写。更早且不满足支持结构的开发库和备份不在兼容范围内，初始化失败时不自动删除数据。
- 118 私有库只增加摘要注入与固定起点字段，旧总开关原子映射为两个同值开关，旧设置、正文和游标保留。
- 120 以前升级表情库所有权，122 以前补齐单聊 Token 显示字段；122 升至 123 时增加收藏表与时间／分类索引，不重建已经完成升级的表情库，也不对收藏建立消息、会话或角色级联外键。已有正文、配置与资产身份保留，失败回滚到原版本。
- 123 升至 124 增加摘要任务和请求设置表，不改旧摘要正文、处理游标或归纳标记；旧摘要没有调用用量记录。
- 当前公开版可能仍有 `call_background_legacy_migration` 文件迁移标记。升级保留它，由 Calls 完成自己的本机文件迁移；新安装不创建该表。

## 初始化所有权

`initDatabase()` 通过 databaseCoordinator 持有一个独占写作用域。`runMigrations()` 在任何新写入前检查版本与支持范围，将 schema、索引、默认记录和版本标记放在同一个事务里提交。索引创建失败也必须回滚，不再只警告后放行。

已经进入基线的库只补建缺失默认记录，不重放 DDL 或历史清理。这样恢复出厂保留物理库结构和版本后，重新初始化仍能建立 Feature 所依赖的默认记录。

当前 schema 是新安装结构的唯一来源。已有 Feature 的独立 SQL fixture 仍可测试其局部约束，不得把旧迁移 helper 重新接入产品初始化。后续版本有真实结构变化时，为已发布基线追加增量升级；新安装定义也要同步更新。

## 已验证

`npm run verify:database-baseline` 覆盖新建库、108／116 旧词表结构升级、117 摘要结构升级、代表性业务数据保留、触发词／手动关系／关闭事实保留、有效/孤立 MCP 授权、消息自增序列、重复启动、建库与升级失败回滚、恢复出厂后的默认记录、SQLite 完整性与外键检查。结构比较使用 SQLite 列与外键契约，不要求 ALTER 升级与新建表的 SQL 文本相同。

实施时另用公开版原始迁移代码生成 SQLite 文件，验证其带数据副本可被新的生产入口升级；该临时实验不把旧迁移链重新保存到仓库中。

## 真机待验收

1. 私有开发版完全卸载重装，启动后创建角色、发送消息、写入记忆，再退出并重新进入应用。
2. 当前公开版覆盖安装新版，确认已有聊天、记忆、摘要与模型配置保留。
3. 恢复出厂后重新配置角色，确认默认记录已重建且聊天能正常使用。
4. 新版备份包恢复，以及当前公开版备份包恢复后的真实原生启动门。

云端的 SQLite 验证不替代 Expo SQLite、Android 文件系统和原生备份流程的真机验收。
