# 辅助模型资产与业务选择契约

辅助模型中心管理模型资产：配置名称、类型、连接信息、参数、启停和连接测试。
实际使用的模型由对应业务系统保存配置 ID。每种能力的首个资产可用后，一次性初始化尚未配置的业务选择；后续模型不覆盖选择。新角色在创建时固化首次 OCR 与 TTS 资产的当前可用引用，之后可独立更换或取消。

`general` 通用资产不参与首次选择或新角色初始化。角色模型设置、群管理员设置从合法草稿复制连接及 Temperature、Top P、Max Tokens；创建角色和群聊时主动选择可用资产，将这些值填入各自配置。副本与原配置之间不保存引用或持续同步关系，停用／删除原资产不影响已复制的角色或管理员。角色资料、上下文和工具权限仍归原 owner。

单聊与群聊的总结模型保存持续引用，一级、二级共用 `modelConfigId`。每次摘要请求解析最新通用配置，不复制连接信息；失效引用保留并显示原因，任务暂停，不自动替换。空引用明确表示单聊当前聊天模型或群聊管理员。修改连接、参数、能力或启停以及删除资产时，Host 在资产事务中调用 Chat owner 撤销引用会话的 claim/generation，旧请求返回后无法提交；名称和资产说明修改不撤销请求。正文、处理进度和引用 ID 均保留。

## 1. 选择所有权

| 使用方 | 持久化 owner | 选择入口 |
| --- | --- | --- |
| 记忆向量化 | Memory：`memory_model_settings` | 记忆首页与召回设置弹窗，全部记忆空间共用 |
| 聊天与通话图片预处理 | Chat：`chat_assistant_image_settings`，按角色保存 | 当前角色模型设置弹窗 |
| 聊天录音、通话 STT | Speech：`speech_recognition_settings` | STT 模型列表顶部直接选择 |
| AI 语音消息、通话 TTS | Assistants：`assistant_voice_settings` | 当前角色模型设置弹窗 |
| 聊天消息翻译 | Integrations：`translation_settings` | 翻译模型列表顶部的「聊天翻译模型」选择 |
| 表情包识别、向量化 | Sticker 自有配置 | 表情包系统已有弹窗 |
| 时刻图片理解 | Moments 自有配置 | 时刻设置已有选择 |
| 单聊／群聊两级摘要 | Chat：`chat_summary_request_settings`，按来源会话保存 | 聊天摘要设置中的总结模型 |

连接信息、密钥与模型资产只保存于辅助模型中心，业务配置不复制它们。
Host 装配资产查询与模型调用端口，不把 Repository 或 SQLite connection 交给其他 Feature。
所有选择保存后立即影响下一次任务；正在执行的任务遵循原有生命周期。

## 2. 解析与状态

`resolveAuxiliaryModel` 只解析调用方传入的配置 ID，没有默认、继承或自动挑选候选的分支。
`getAuxiliaryModelSelection` 返回候选与当前引用状态，和执行解析共用可用性规则。
停用、删除、能力类型不匹配、连接信息或语音、翻译 Provider 配置不完整时，显示不可用原因。
当前引用独立于候选列表读取，因此停用或删除不会被误显示成未选择。

业务选择保留失效模型的 ID，用于展示原因；用户取消选择才清空。
可用表示本地配置满足调用条件，不保证实时网络、鉴权或额度正常。请求失败由原有调用链处理。
模型资产变更提交后发布变更信号，由 Host 通知对应设置投影刷新。

### 2.1 首次配置与新角色初始化

Assistants 在 `auxiliary_model_initial_defaults` 按能力记录首个配置 ID 和初始化完成标记。它只用于创建时初始化，不参与任务解析，也不保存连接信息。

- 首个资产与默认记录、各 owner 的初始选择在同一事务提交；失败全部回滚。主键与事务保证并发创建只有一个首次模型。
- 首个配置停用或凭据未填完整时暂不生效；该配置后续可用时完成一次初始化。第二个模型不会抢占首次身份。
- OCR 初始化各角色 Chat、Moments 与 Sticker 识别选择；TTS 初始化各角色声音选择；STT、translation 初始化对应全局选择；embedding 初始化 Memory 与 Sticker 向量选择。
- 已保存的角色选择行（包括显式取消的 NULL）不覆盖；全局与 Sticker 只填空引用。完成标记阻止后续创建或编辑重放初始化。
- 新角色与其 OCR、TTS 初始选择在同一事务提交，使用同一可用性判定。首次资产停用、删除或类型不匹配时不改用其他模型；默认记录保留删除后的 ID。
- Host 只组合各 owner 的事务入口。事务内只写 SQL；commit 后复用资产刷新信号与 Sticker 队列唤醒，Memory 的指纹、revision 与 claim 仍由原队列处理。

语音提供方与参数契约归 Speech，Assistants 的语音表单和资产可用性解析复用同一校验。官方地址自动填入，只有自定义兼容服务要求用户填写地址；已有非官方地址由用户明确决定是否更换。测试调用读取当前合法草稿快照，不提交选择、消息或媒体资产。Chat 语音工具在 run 准备时固定角色 TTS 快照及支持的表达参数，避免工具 schema 与执行模型在用户切换配置后错配。当前提供方与扩展入口见 [Speech README](../../src/features/speech/README.md)。

通用 `ConfiguredModelPicker` 只负责展示与交互，查询、保存和刷新信号由 owner 提供。
业务设置页可提供管理配置入口；控件已嵌入资产列表时不额外提供管理跳转。模型变更信号刷新候选与当前引用。

## 3. 消费行为

- Memory 全部空间共用其系统选择；切换仍经过原有模型指纹、revision、claim 与队列取消契约，UI 不直接创建向量任务。
- 每个角色独立选择视觉识别模型，模型选择本身就是图片路线，不再另设预处理开关。
- 未选择或取消选择时，原图直接交给当前聊天模型，由用户确认该模型支持图片；不使用能力标记或模型名白名单拦截。
- 选择后先识别，再把文字转述交给聊天模型；所选模型失效时进入 `vision_unavailable`，识别请求失败时提供失败文本，不自动改为直传。
- 通话图片继续复用 Chat 的图片输入解析，不建立第二套图片模型选择。
- 聊天录音和通话共用 Speech 的 STT 选择，consumer 标签不产生额外配置层。STT 列表内嵌现有选择控件，原「我 → 语音识别设置」入口与页面已移除，已有选择无需迁移。
- TTS 只读取当前角色的明确选择；首次模型与新角色创建可初始化该选择，取消或未选择时不可用，不跟随其他角色或运行时默认。
- 聊天翻译入口先显示 `translation` 模型列表，AI 与腾讯云配置共同展示，列表内直接选择聊天翻译使用的配置。资产管理复用 Assistants，实际选择仍由 Integrations 保存，无独立设置页。提供方契约归 Integrations，资产可用性解析与输入校验复用同一契约。AI 翻译复用 Platform 的 OpenAI 兼容客户端，不限制模型名；翻译提示词只消费原文，不继承聊天上下文。所选模型失效时明确失败，不自动挑选其他资产或提供方。

## 4. 升级与备份恢复

迁移95在同一事务内：

1. 把旧启用的 embedding、OCR、STT 选择转到各 owner 的配置。
2. 保留角色明确的 TTS 选择和停用状态；把原先继承的旧全局 TTS 一次性固化为角色选择。
3. 保留失效引用，不根据候选自动选模型。
4. 删除 `capability_bindings` 和 `assistant_capability_bindings`，提交 `PRAGMA user_version = 95`。

旧版 OCR 角色绑定先由历史迁移88转换图片策略，再进入此次迁移；历史多模型冲突仍不武断选择。
转换失败则整个事务回滚，包括版本标记；修正失败原因后可完整重跑。
后续启动与新版快照恢复按版本标记跳过旧绑定表的创建与转换，不重写用户的新选择。
新 schema 不包含旧绑定表，数据库备份格式仍为完整 SQLite 快照，版本标记与业务选择一并保存。

旧 capability binding 的运行时继承、默认 UI 和全局绑定 API 不再存在。首次初始化写入各 owner 的明确选择，不恢复旧绑定表或运行时继承。
历史升级脚本仅服务旧数据库升级，不提供运行时兼容回退。

迁移96在同一事务内，把旧 Chat 全局视觉选择复制给原先开启预处理的角色，保留失效引用；原先直接传图的角色保持未选择。随后删除旧 `chat_image_settings`，提交版本96。旧 `image_processing_mode` 列仅用于历史升级，不再进入角色实体、设置草稿或运行时判断。新角色的视觉选择由当前首次配置规则初始化，删除角色时选择随身份级联删除；重启和快照恢复不重放旧开关。

迁移106在同一事务内将 `external_service_configs` 中的翻译记录转换为 `translation` 资产，保留凭据、参数、启停、名称与时间戳，并将原来实际使用的配置固化为 Integrations 的明确选择。历史退休的 `translate` 资产不恢复使用。仅删除已经转换的外部翻译行；其他历史服务行不在迁移范围。失败时全部回滚；版本标记随选择进入备份，新版启动与快照恢复不重放迁移。

迁移108只记录每种能力按创建时间最早的旧资产，并标记已有安装的首次初始化完成，不回写旧业务选择。新角色可使用当前可用的首次资产；停用或删除时不自动选择第二个。迁移 marker、资产 ID 与业务选择一并进入完整 SQLite 快照，重启与恢复不重放初始化。

## 5. 验证

`verify:auxiliary-model-runtime` 验证真实 SQLite 首次选择、新角色初始化、并发唯一默认、取消与改选、未完成配置、停用与删除、事务回滚、升级与快照恢复，以及原有 Host 语音选择装配、角色视觉选择隔离和图片路线。
`verify:translation-settings` 验证翻译资产管理、业务选择、迁移回滚与快照恢复、提供方草稿切换、模型发现和真实客户端请求。
`verify:memory` 继续验证向量 CAS、重建、晚到结果隔离及恢复；通话与聊天语音分别使用已有专项验证。
