# 对话两级摘要

## 所有权与用户记录

Chat 的 `summary/` 拥有单聊与群聊的一级、二级摘要、会话设置、处理进度、持久 claim 与查询。群摘要归群会话所有，管理员只是执行者；更换管理员、模型或成员不改变摘要归属。Host 装配实际所选模型、Calls 事实、提示词和共同前台维护队列。SQLite 访问经过 databaseCoordinator，模型调用在事务外。

群一级触发使用群设置 `groupTriggerCount`（默认 40），不读取成员主·群聊或管理员调度窗口。群仍在准备／执行 plan 时不领取一级范围，未完成响应的用户输入保留。主客上下文的只读来源查询不推进摘要处理游标。

两级正文都是用户拥有的记录。用户可以编辑、删除，清空操作同时清除两级摘要；删除消息或清除聊天历史不删除已保存摘要。两级独立维护，编辑或删除一级不改写已形成的二级，编辑二级也不修改一级。需要同步时由用户分别修改。

聊天中的 AI 可通过记忆工具包显式编辑、删除一级记录，编辑二级正文；自动总结任务仍只能追加，不因工具开放而获得改写旧正文的权限。

`compaction_id` 表示一级摘要已被哪次归纳消费，是持久处理标记而不是正文外键。删除二级摘要不清除该标记，不自动补回二级，也不恢复注入对应一级。用户删除一级后，原摘要不能检索，但二级中已有的内容仍保留，直到用户自己修改或删除它。

## 设置与上下文

设置按来源 canonical 单聊或群会话保存，缺少覆盖记录时采用明确默认值：自动生成开启，已有摘要注入开启，二级摘要开启，一级待归纳正文阈值 8000 估算 token，无固定消息起点。摘要请求默认最长等待 300 秒，输出额度默认继承实际所选模型的配置；独立覆盖只影响摘要。各来源设置独立。

- 自动生成开启、无固定起点：原文从摘要处理游标之后读取，未总结部分不裁剪。已有摘要按独立注入开关选择；摘要与原文从同一事务快照取得。
- 仅关闭二级摘要：暂停归纳，不注入二级正文，恢复注入现存一级摘要。
- 自动生成关闭、无固定起点：两级都停止生成，绕过摘要游标读取最近 N 条逻辑对话；已有摘要是否注入由独立开关决定。单聊 N 使用“主·单聊”，群聊 N 使用当前成员“主·群聊”，当前输入单独保护，同一逻辑消息的多个分段只占一条。通话原文遵循同一窗口。
- 关闭已有摘要注入：两级旧正文都不自动注入，不删除记录、不关闭生成，不影响生成请求中的只读摘要背景。主动查询仍可使用。

开关不删除正文、不回退处理游标。再次开启继续已有处理进度，仍保留的未处理消息可以进入下一次一级任务。主动查询工具与自动注入开关分开，关闭时仍可显式查询。

## 固定消息范围

对话设置在上下文条数下方提供入口，没有起点时显示“去设置”，通过现有导航意图由 Host 的 Expo Router 返回消息列表。已发送、可进入上下文的用户／AI 消息长按菜单提供“固定”；当前起点提供“取消固定”。更换起点只替换引用。选择具体气泡时从该气泡开始，不补回同一逻辑回复的更早气泡。

固定保存 `fixed_message_id`，不保存正文副本或摘要进度副本。Repository 在同一事务验证消息所属会话、可见范围和已发送状态，保存起点、关闭两级自动生成，并以 generation 撤销在途提交资格。固定期间不允许重新开启生成。已有摘要注入开关、二级配置、近期条数和原处理游标保留。

固定原文从起点（包含该消息）按 canonical 顺序读取到最新，不受近期 N 或摘要游标裁剪。通话历史只保留起点时间之后的部分；Current Input 仍单独保护，重写请求仍遵循历史上界。设置页面从当前事实显示起点内容和范围内逻辑对话条数，计数包含最新消息，应用事件不占条数。

取消固定只清引用；删除起点由消息外键 `ON DELETE SET NULL` 统一取消，单条、多选和重写替换删除无需各建一套副作用。清空聊天是隐藏历史，由清空事务同时清起点。三种情况都不恢复生成，也不改已有摘要注入选择。恢复近期 N 窗口后，用户手动开启生成才沿原游标继续处理积压，不从曾固定的消息重来。

## 一级生成

沿用聊天与通话的统一时间线和 N 门槛：通话中达标等待终态，跨入已结束的电话时闭合完整范围。一次领取的全部新原文在一次模型调用中整理，成功后原子追加正文、普通消息游标及已处理通话标记。单聊的 N 默认跟随该 AI 的单聊主视角条数，摘要设置中可手动固定为其他值；手动固定后不再跟随。原文超出模型上下文时归类为上下文溢出，任务彻底失败并提醒用户调小「每次整理条数」或换用上下文更大的模型，不重试同样范围。提示词要求新增正文控制在 500 字以内；500 字不是落库边界，正文非空且服务端未报告截断的结果即使超出也完整保存，不裁剪、不为字数重复请求。

一级、二级均只要求模型返回摘要纯正文，不使用 JSON 输出包装。Host 的模型请求边界去除首尾空白，拒绝空正文与服务端明确报告的截断；Chat 信任该契约，直接提交正文，不再做 JSON 解析或重复非空校验。模型输入仍使用结构化 JSON，来源范围、身份和日期锚点保持明确。

规则集中于重要事件、实体、约定、长期偏好、结论与未完成事项，不复述聊天往返、动作、称呼和短暂情绪互动。只处理领取批次，已有摘要是只读背景，不改写用户旧正文。

## 二级触发与交接

每次一级追加或用户修改摘要／设置后，由同一前台队列检查所有尚未归纳的一级正文。token 使用 shared 的稳定近似估算，只统计这些正文，不包含已有二级、静态提示词或剩余原文。

例如阈值 8000，前五批合计 7999 不触发；第六批保存后合计 9000，就领取全部六批，而不是截取前五批或裁剪到 8000。领取后固定来源快照，期间到达的第七批属于下一轮。

二级只归纳领取的一级摘要，提炼重要事件、实体与关系，不读取原始对话，不合并或递归改写旧二级。输出只允许 `{ "content": "正文" }`，摘要输出额度默认跟随实际所选模型配置，也可独立设置；规则要求显著压缩、独立可读，不设目标字数。归纳触发阈值不是输出额度，也不是整个聊天上下文的硬性上限。

提交事务同时保存二级正文和全部来源归纳标记。生成期间原一级仍进入上下文；失败、取消、非法模型结果都不交接。提交后按领取批次首段的稳定序号放置二级，避免第七批先保存时造成新旧记忆倒序。

一级与二级共用会话持久 claim／租期。同一范围最多一个 winner。领取事务同时冻结总结模型引用、超时、输出额度，提交时检查领取资格。来源在请求期间被编辑、删除或已消费时拒绝旧结果；新增来源不使领取批次失效。设置变更、清空摘要通过 generation 撤销旧任务。被引用辅助模型的调用参数或可用性变化、删除也在资产事务中撤销资格，保留正文和进度。已经形成的二级不再监听来源正文的变化。

前台队列只有一个 running 任务。`chat_summary_work_queue` 保存需要重新检查的会话和检查水位；消息原文、通话、回复游标、群发言终态、摘要与相关配置变化随事实同事务入队。内存集合只合并提交后的唤醒，不拥有待处理事实；后台没有运行队列或进程退出也不会丢失工作。进入前台只读取持久待检查身份、到期重试和失去有效租约的在途任务，不遍历全部会话或读取正文发现工作。数据库 142 升级事务仅为旧版本既有来源补一次待检查记录，后续启动不再补扫。

未达到门槛或暂不可领取时，只确认本轮开始前读到的队列版本；并发到来的新事实保留更高版本，不能被旧检查确认。取消和本地故障不推进水位；生成成功后继续消费该会话积压。重试任务由自己的状态、冷却和租期决定何时重新可消费，失败暂停不会因重新启动被复活。每轮先检查已有一级是否已达到二级阈值；否则处理一批一级并在提交后再次检查。因此降低阈值不必等待新的一级生成。两层分别记录失败与冷却，共用同一持久 claim，某一层失败不阻止另一层处理自己的范围。backlog 不会并行启动两种摘要，二级期间新原文继续保留。

领取事务先裁决任务暂停、冷却和手动意图，再读取原文、通话或待归纳正文。一级原文按 canonical 游标分页，读到本批之后的原文才能确认范围；跨页逻辑分段完整保留，跨入通话仍闭合到结束，待回复输入与未终结自主过程继续保护。分页只缩小领取扫描，不切分模型调用，不改变 claim／generation 的原子交接。用户正在等待的摘要／原文上下文读取使用 interactive 优先级，可延后的领取与维护仍使用 maintenance。

## 任务、诊断与有限重试

`chat_summary_tasks` 保存会话／级别、执行状态、尝试次数、自动失败次数、下次重试时间、最近错误、调用元数据与生成的摘要 ID。任务不是摘要正文，不进入自动上下文或摘要搜索。成功时与正文、处理游标／归纳标记同事务交接；用户删除摘要不复活记录。旧版本和手动摘要没有用量，不推测补造。

两级的网络、过载、超时、空正文与交接失效（领取被撤销或租约过期导致结果未保存）只允许一次自动重试，包含首次共两次自动尝试：第一次失败后等 120 秒，第二次失败暂停。明确输出额度耗尽、原文超出模型上下文及可靠 HTTP 鉴权／参数错误直接暂停，上下文溢出会在任务彻底失败时提醒用户。交接失效记账后任务才允许重新领取，不会用同范围静默重试。新增消息不刷新失败次数，用户修改请求参数（含每次整理条数）后重新评估。手动重试只排队一次，失败仍暂停，不开启新的自动循环；提高二级触发阈值不阻止明确的手动重试。所有状态进入 DB 备份，重启不重置计数；切到手机桌面取消在途请求不计失败，回前台继续，并保留手动请求的性质。

队列每轮通过 `prepareChatSummaryConversations` 准备会话。Repository 同事务收口旧版本已失败两次、仍等待第三次的任务和已经过期的自动在途任务；不重置预算，不再补请求，保留错误与调用信息。手动意图及仍有有效 claim 的在途任务不被此准备撤销，事务提交后才刷新页面。任务尝试次数包含手动和取消后恢复；一次任务只调用一次模型，不能把历史累计次数当作自动重试次数。

模型适配保留服务端结束原因、输入／输出／总／缓存 token、正文与思考字符数、请求额度、耗时和服务端错误；服务端没有提供的值显示未知。请求超时明确标记为本地超时，不再把 AbortError 当成服务端错误。正文或思考内容、提示词与凭据不写入诊断。完成后保留最近失败及各次调用信息供调试，包括历史任务已经保存的格式错误。

Chat 任务拥有重试，摘要请求关闭底层 reasoning-only 自动扩额度重试。输出为 `length` 时不提交半截正文。请求 timer 与 claim 租期一起计算：租期为请求最长等待加 60 秒，一次调用只持有领取时的租期，不再分片续租。SQLite 故障继续由原持久化边界暴露，不作为模型请求失败吞掉。任务状态通知只刷新页面，不触发队列自身重试；摘要事实与用户设置变更才唤醒调度；上下文溢出导致的彻底失败额外弹窗提醒。

## 页面

群聊信息页的「聊天摘要」入口复用一级列表、二级正文、编辑、设置与诊断。设置中一级、二级共用总结模型；群页另有全群触发条数，单聊页另有每次整理条数（留空跟随该 AI 的单聊主视角条数，手动填写后固定）。导航仍由 App 路由适配，Feature 只表达意图；没有另建群摘要任务流程。

主列表用一个二级入口展示全部归纳正文，一级列表只显示尚未归纳的记录。层级标签保持紧凑，正文、设置和诊断通过共享 `ThemedSurface` 接入主题表面；玻璃主题使用现有原生玻璃材质，普通主题使用对应表面色，日期使用可读的次级文字色。

二级编辑页只有一个正文编辑框，按上下文顺序拼接现存二级正文。保存时 Repository 在一个事务中合并正文与来源关联，保留最早的上下文位置和覆盖讨论时间，原一级正文、处理游标和调用事实不变。编辑期间有新二级或其他正文修改时，CAS 拒绝覆盖，页面保留草稿。新生成的二级仍独立交接，再次打开时纳入同一个编辑框，不递归让模型改写旧二级。

已归纳的一级记录只在二级页按讨论时间排列，展开后点击编辑；修改或删除来源不自动改写二级正文。卡片标注“保存于”，展示应用记录的摘要创建时间，不展示首条来源消息日期；讨论时间仍用于历史排序、模型输入和查询，不混作生成时间。来源和调用记录随会话事件刷新，不覆盖二级草稿。删除全部二级正文不解除归纳标记，原记录仍可在这个入口维护，调用信息仍可展开查看。

失败／等待／生成中的任务仍单独可见，失败条目标注“失败，查看失败原因”，详情展示错误和调用数据。重试只提交意图，不占用页面等待模型，不弹成功提醒，用户可离开页面继续使用 App。成功一级编辑页保留调用信息，成功二级调用集中在二级页查看。

独立“摘要设置”路由保存开关、归纳阈值、最长等待秒数和输出额度。输入停止 1 秒自动保存，失焦立即保存，离开页面先确认草稿；非法输入与写入失败保留输入，开关独立提交。所有导航由 App 的 Expo Router 适配，Feature 仅表达意图。

## 提示词与查询

一级、二级共用一个模型选择。单聊默认当前聊天模型，复用基础规则、人设、用户身份、协议空间、长期静态片段和相同工具用途目录，任务规则放在稳定前缀之后。选择通用辅助模型时只提供专用总结规则、必要来源身份、领取输入和只读摘要背景，不继承聊天人设或工具目录。

群聊默认管理员，也可持续引用通用辅助模型；两种选择使用同一套中立群总结提示词，不带调度提示词。输入标注公开参与者身份，总结主题、重要观点、共识、分歧、约定、分工和进展，不逐句复述，不把个人意见当作全群共识。参数、默认输出额度与诊断来自实际模型。失效配置保留引用并显示原因，不自动替换。

所有摘要请求均不执行工具，不读取社交、被动记忆、电量、当前时间、工具展开状态或批次外未总结原文。一级输入包含本批原文与已有摘要背景；二级输入只有待归纳摘要。

记录自身的讨论时间／时区和明确事件日期保留。讨论日期不冒充事件日期，相对事件时间按原文自己的日期锚点解释，不根据当前请求时间重写旧事实。前缀复用有利于服务商缓存，但不承诺必然命中。

`search_chat_summaries` 是 Chat 拥有、Host 放入记忆工具包的只读工具。身份来自可信 Agent task，模型不能指定其他 AI。支持 ISO 时间范围、关键词任一匹配与每页 20 条分页；时间按讨论范围相交筛选，手动记录采用保存时间。两级和已归纳原摘要均可查。每页读取当前数据库，不缓存已删除正文，结果只是历史资料，没有指令权限。

`edit_primary_summary` 和 `delete_primary_summary` 使用查询结果中 `level: primary` 的记录 `id` 作为 `segmentId`，定位一条记录。编辑支持 `replace_text` 唯一片段替换与 `replace_all` 整条替换，原文通过 `oldText` 匹配；删除必须传入刚查询到的完整 `expectedContent`。目标不属于指定会话、不是一级、无权访问或原文已变化时拒绝写入。一级编辑不合并记录，保留原 ID、位置、讨论时间、归纳标记与创建时间；删除只删除目标一级记录，不删除聊天原文、不回退处理进度、不改写已有二级。若目标属于在途二级任务的领取来源，旧来源快照将失效，不允许旧结果提交。

`get_secondary_summary` 按上下文顺序读取一个来源会话的完整二级正文，不受注入开关影响。`edit_secondary_summary` 提供 `replace_text` 局部精确替换和 `replace_all` 全文替换：两者都接收 `oldText` 与 `newText`，局部原文须唯一匹配，全文模式须与当前完整正文一致。局部允许删除片段，但最终正文不能空白；没有二级正文时不能借编辑新建。原文不匹配时返回可读错误，不自动重试。默认来源是任务会话，也可指定自己的单聊或仍参加的群。

摘要维护工具由 Chat 拥有并放入记忆工具包，单聊与群聊按原工具授权暴露。身份和群成员资格在 Repository 的同一事务内确认，原文匹配后复用页面的持久化交接，保留讨论范围、原文游标与调用事实。全文替换拒绝覆盖读取后变化的正文；局部只修改仍唯一匹配的片段，保留其余当前正文。提交后发送同一摘要变更事件，页面与后续上下文读取新事实。

## 验证

摘要工具默认当前任务会话；身份来自可信 Agent task，只允许自己的单聊与仍参加的群。群中沿用同一套摘要读取、一级编辑／删除与二级编辑工具，不新增群原文获取工具。

数据库版本 126 增加模型引用与群触发条数，新建库及升级使用相同 schema，完整 SQLite 备份保留正文、设置和进度。`verify:auxiliary-model-runtime` 验证配置修改、停用、删除与任务资格一起提交／回滚；`verify:memory` 验证群两级交接、来源读取与实际所选模型调用。

`npm run verify:memory` 覆盖一级原文交接、完整超阈值批次、第七批隔离、排序、两级独立编辑删除、固定范围、AI 隔离、开关独立、删除／清空起点、沿原进度续接、generation、唯一提交、回滚、有限重试、取消恢复、调用诊断、检索隔离、页面草稿与离开保存及备份恢复。`verify:database-baseline` 覆盖保留的历史版本及 123 到 124 的升级、新建库和事务原子性。118 的旧总开关映射为生成／注入两个同值开关，不改正文与进度。真实模型摘要质量、Android 前后台与页面体验仍需设备验收。
