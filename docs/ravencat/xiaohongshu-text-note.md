# 小红书文字笔记

工具包只支持「写想法 → 文字卡片 → 笔记编辑 → 发布」路线，不进入或填写写长文。AI 逐步选择工具，原生每次只执行当前语义步骤；旧 `xiaohongshu_prepare_text_note` 整段编排已删除，不保留并行旧路径。

普通 Chat 的工具往返预算为三十轮，调用总数仍最多三十次、每批最多三次；工具额外保留无工具最终回答，Android 后台截止不变。这样 AI 可以逐步观察，而不是为了十轮限制提前编排整条流程。

## 工具与页面

| 工具 | 当前步骤 |
| --- | --- |
| `xiaohongshu_get_page` | 只读确认前台身份、实际页面、键盘状态和可执行步骤，失败后也可调用 |
| `xiaohongshu_enter_publishing` | 从小红书主页面打开创作菜单 |
| `xiaohongshu_open_text_entry` | 选择写文字，停在写想法 / 写长文分叉页 |
| `xiaohongshu_start_text_note` | 选择写想法，进入文字卡片输入页 |
| `xiaohongshu_set_card_text` | 设置卡片文字，保留换行，不生成或发布 |
| `xiaohongshu_next` | 在卡片输入或样式预览页只点击一次下一步，返回实际到达的页面；应用可能跳过预览 |
| `xiaohongshu_select_style` | 选择前五个可见样式槽位，已选中时不再次点击换搭配 |
| `xiaohongshu_set_title` | 设置笔记标题 |
| `xiaohongshu_set_body` | 整体替换正文，之后需要重新添加话题 |
| `xiaohongshu_add_topic` | 只添加一个精确话题，返回本次结果；已有同名话题文本时不重复粘贴 |
| `xiaohongshu_set_visibility` | 设置公开或仅自己可见 |
| `xiaohongshu_go_back` | 返回一次；有键盘时先收起，遇到保存 / 放弃确认时不自动丢弃内容 |
| `xiaohongshu_prepare_publish` | 在待发布页核对内容并取得一次性凭据，不点击发布 |
| `xiaohongshu_publish_prepared_note` | 消费凭据，只尝试一次发布 |

每步返回 `status`、`step`、`actionAttempted`、`publishAttempted` 和现场 `page`。页面包括 `kind`、人类可读的 `label`、前台包名、窗口 ID、可靠性、键盘状态、有界输入摘要、可见标签和 `availableActions`。可区分首页、主页面、创作菜单、分叉页、卡片输入、样式预览、笔记编辑、可见范围、离开确认、写长文、发布成功、其他应用、未知页面和窗口不可读。

输入摘要每个字段最多 180 个 UTF-16 单元并标明截断，可见标签最多十六项、每项一百单元。不返回完整节点树；只读身份可报告其他应用包名，但不读取其他应用内容。小红书内容仍受 Protected Apps 准入限制。

## 失败与重新决策

原生不会自动重试、回退到其他输入方式、返回或重跑整段流程。非发布失败返回 `not_completed`，保留实际页面、所需页面和原因；AI 先确认现场，再决定下一步或显式重新调用。只读确认不点击、不恢复页面，也不伪造预期步骤已成功。包名可靠的小红书未知页面允许显式返回；已打开的可见范围选择页允许继续选择，不必先退回重走。

Legacy adapter 在失败时只向模型投影 `error` 文本，所以页面事实同时序列化进失败文字，不能仅放进 `data`。否则日志保存了页面，模型仍然只能读到一条模糊错误。

单步最多二十秒，页面条件最多等八秒；等待只观察结果，不重放动作。取消通过原生预约 ID 传递，同一进程同时只执行一个小红书步骤。屏幕变化、输入结果不符或遮挡都报告当前现场。原生 `RavenCatXhsStep` 日志只记录步骤、状态、页面类型和是否尝试动作，不记录文案、话题、凭据或页面文字。

切页期间窗口身份可能暂时不可读，结果确认会在原有时限内等待可读事实恢复，不把第一次缺失当作操作失败；明确切到其他应用则停止。成功返回用于确认结果的那份页面，不在成功后再读取一次窗口覆盖结果。`not_completed` 只表示未确认，不能据此断言动作未生效。离开确认页不提供自动操作，包括再次返回；需用户处理。

## 输入、适配与所有权

卡片、标题和初始正文使用 `ACTION_SET_TEXT`，在原生聚焦对应可编辑字段，等待焦点事实后输入。卡片最多三百、标题二十、正文五百个 UTF-16 单元。输入框位置随键盘变化，字段按当前笔记页的两个编辑控件识别，不再依赖固定纵坐标来判断填写结果。不处理密码框。

话题工具每次只接收一个不含 `#` 和空白的精确名称，最多二十个 UTF-16 单元；打开话题入口、核对正文末尾光标后，覆盖系统剪贴板并执行 `ACTION_PASTE`，等待小红书识别话题并补空格。该操作会改变剪贴板，不读取、缓存或恢复原内容。已经添加话题后，不应整体改写正文，除非准备重新添加话题。

节点动作列表是获取节点时的快照，粘贴能力还受剪贴板当时内容影响（见 [Android TextView 源码](https://github.com/aosp-mirror/platform_frameworks_base/blob/android14-release/core/java/android/widget/TextView.java#L13942-L13947)），不能在写入话题前据此拒绝输入。原生验证焦点、可编辑状态及末尾光标后先写剪贴板，只派发一次 `ACTION_PASTE`，以实际返回值和上层正文核验确认结果，不刷新动作列表或切换输入方式重试。

粘贴后先收起键盘及其话题输入浮层，再在笔记正文页核对精确话题，避免浮层缺少语义字段造成“已添加却报未确认”。这一步不处理系统分享或双开应用选择弹窗，也不补点候选话题。

区域点击仍使用已采集小矩形和 150–450ms 的有限随机节奏；不再自动插入整段流程中的样式浏览滑动，避免改变下一次工具调用面对的页面。节奏不承担就绪判断，也不承诺避免平台风控。

部分机型与版本适配。内部设备条件为 vivo V2244A、1080×2400、480dpi、默认字号；外部说明不展示这些参数。已采集的小红书版本为 9.51.0 和 9.52.0，仅作维护记录，不设置精确版本、最低版本或未来版本范围。页面变化后更新本适配，不建设多版本策略或通用坐标执行器。

Phone Tools 持有主理身份、单项权限、星标和 Protected Apps 准入；Registry 是唯一工具执行入口。原生适配借用 Device Observer 的同一窗口事实和无障碍服务，后台执行继续由现有 Agent run 宿主持有，不新增永久保活或 Overlay 依赖。

## 发布凭据

`prepare_publish` 只在已识别、键盘收起且可见范围明确的笔记编辑页发行十分钟内有效的进程内凭据，绑定 AI、窗口、标题、正文和可见范围。调用编辑或导航步骤使凭据失效；只读确认不使其失效。凭据不是图片像素校验，检查期间不要换图或切换账号。

派发发布前原子核对并消耗凭据。只观察到发布成功页面才返回 `published`；一旦已经进入发布派发阶段，任何结果不明均为 `publish_outcome_unknown`，禁止自动重试或重新取得凭据重发，只能只读确认页面，仍不明时请用户检查。进程重启不会恢复凭据，也不重放发布。
