# 上下文主客配置与摘要门槛

本文定义现有四项上下文配置的归属与适用范围。普通单聊、通话实时回复和去电决策共用消息范围：自动生成时读取未总结原文，暂停生成时读取最近 N 条逻辑对话，固定起点时读取从选中消息到最新的完整范围。两级旧摘要按独立注入开关决定。当前契约见[对话两级摘要](../architecture/chat-summary.md)。

## 1. 当前范围

四项配置均已接入。单聊读取自己的主·单聊与全部当前已参加群的客·群聊；群聊读取自己的客·单聊、当前群的主·群聊与其他已参加群的客·群聊。当前群只注入一次，群额度按每群计算，退出或删除后不再自动带入。

## 2. 主客相对性

主表示上下文来源就是当前交互主场，客表示同一来源作为其他场景的背景。主客是来源与场景的关系，不是第二套消息或摘要。

| 来源 | 主 | 客 |
| --- | --- | --- |
| 一对一会话 | 单聊与通话共享的来源 | 其他场景读取该会话背景时的展示配置 |
| 群聊会话 | 当前群场景 | 其他场景读取群背景时的展示配置 |

主条数必须为正整数；客条数允许为 0，也允许高于主条数，不增加大小关系限制。

## 3. 持久化所有权

Assistants 的 AIProfile/ai_assistants 持有四个模型行为设置；不保存到 Prompting 编排表：

| 字段 | 默认值 |
| --- | ---: |
| privateContextPrimaryLimit | 30 |
| privateContextSecondaryLimit | 10 |
| groupContextPrimaryLimit | 40 |
| groupContextSecondaryLimit | 5 |

共享默认常量位于 `src/shared/prompt/contextWindowLimits.ts`，只是配置默认值，不授予新的查询能力或建立新的业务 owner。

## 4. 普通单聊、通话与自主执行

Chat 拥有摘要处理状态、固定起点与 canonical 投影，Host 经 `PromptHistoryBuilder` 按同一事务快照装配。生成开启时转写与普通消息共用摘要计数，未处理原文不被窗口裁剪；暂停且无固定时按 N 读取最近逻辑对话，绕过摘要游标和已处理通话标记。固定时停止生成，从所选消息到最新全部注入，不改原摘要进度，已有摘要注入独立控制。

AI 日程只有一次正常自主执行，没有独立的先客后主决策模型或 `raven_cat.proactive_decision` 链。沿用共同 Prompt 装载，不增加新的后台唤醒。来源按类型和会话 ID 稳定排序，不按活跃时间重排；背景复用已有 `conversation_summary` 区块并标记为没有指令权限的历史资料，保持稳定前缀。

## 5. 计数与原文保护

有正文的 canonical user/assistant 消息与通话真实转写参与摘要计数；系统状态、工具事实和 TTS 分句不重复占额度。Current Input 单独保护，不在历史中再次出现。

摘要提交前保留完整待处理原文，提交后才按同一事务的 watermark 交接。N 不授权在等待摘要时裁剪原文，也不增加自动 token 裁剪。

## 6. 摘要生成与客展示

通话中达到 N 等待终态，短通话继续累计；一次领取的全部原文在一次调用中整理，成功后原子追加摘要和进度。AI 只追加，用户可维护旧段；删除消息不删除已有摘要。

摘要属于来源会话。客展示配置不改变生成批次、处理游标或旧摘要，不触发重切、递归压缩或重新生成。客读取在同一快照内取得身份、成员关系、近期原文与摘要，绕过来源处理游标和固定起点，属于只读查询。

客条数为 0 时，该类来源的原文和摘要均不注入，但来源自己的摘要生成继续；正数只限制近期原文，摘要另遵循来源自己的注入开关。单聊摘要仍由主·单聊条数触发；群摘要使用全群独立的 `groupTriggerCount`，不读取成员主客设置或管理员调度窗口。

跨会话原文与摘要遵循执行输入上界，不能带入后来到达的输入。群主视角允许本 plan 已提交的前序成员发言进入后续请求，后来用户输入仍不得越过本轮上界。分享记录继续按当前 AI 的 agentId 投影，公开参与者名称不含其他 AI 的备注昵称。

## 7. 设置 UI

`src/features/chat/presentation/conversation/ContextWindowSection.tsx` 在对话设置页展示单聊·主、单聊·客、群聊·主、群聊·客输入，通过对话表单与助手设置命令保存，沿用现有助手字段。

页面说明包含主客组合、每群额度、0 的效果和摘要规则。草稿边界验证输入；Repository 和下游信任保存契约，不重复补值。自动保存行为见[对话设置契约](../architecture/conversation-settings-autosave.md)。

快捷操作先保存合法草稿，选择目标或全部 AI，在一个事务内只复制四项数值；目标消失时整批回滚。之后各 AI 独立修改，不复制摘要设置、人设或权限，不建立全局继承体系。

条数区下方的固定起点入口返回消息列表，由长按菜单选择。固定期间仅“单聊·主”暂时禁用，保存值不改；入口显示当前起点内容与逻辑对话数。取消／删除起点后恢复输入，摘要注入选择不变，生成仍暂停直到手动开启。

## 8. 验证与范围边界

`verify:memory` 保护主视角原文、客窗口、每群额度、0、来源开关、退出群、当前输入、后续输入上界、只读进度和摘要身份隔离。`verify:auxiliary-model-runtime` 保护批量复制与独立修改／回滚，`verify:conversation-settings-autosave` 保护主客整数边界。真实模型效果和页面操作仍需设备及服务验收。
