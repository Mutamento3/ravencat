# Calls

Calls Repository 是通话会话、事件与附件的唯一业务真值。`AICallRuntimeService` 在提交状态后更新消息时间线和原生投影；接听、拒接、去电决策和挂断通过 Repository CAS 提交，晚到决策不能复活终态。

启动恢复先按通话 ID 查询原生执行宿主；页面重新挂载而宿主仍存活时，不提交故障终态，也不回收该通话快照。重复挂断已是终态的通话仍释放媒体并完成 Headless 等待，只保留首次终态事实，不重写结束原因、状态气泡或重复触发跟进。

持续执行入口位于 Host：`CallExecutionHeadlessTask` 先等待备份恢复和普通 SQLite bootstrap，再创建唯一 `CallMediaRuntime`，等待通话终态、输入退场和命令回执后释放原生宿主。媒体仍复用统一用户输入、Call reply run、TTS 队列、ASR 与快照持久化链，没有独立后台回复流程。

`modules/call-runtime` 持有每通电话的前台服务、独立唤醒锁、Core-Telecom、音频 endpoint、CameraX 和系统通话窗口。`call-audio-playback` 只播放音频。悬浮权限仅控制窗口，通话执行不依赖 RavenCat 悬浮球或 Companion 服务。

Expo bridge 的生命周期回调是线程边界：前后台变化与 React 销毁都交给主线程处理窗口、CameraX 与执行清理。销毁清理不依赖随后取消的模块 scope，并按 ReactContext 身份只释放该实例的通话。通话执行期间通过共享 Overlay 可见性契约抑制普通悬浮球，结束后释放抑制；不改变小球开关，不停止 Companion 或悬浮球 Service。

`CallRuntimeProvider` 只订阅媒体状态并投影当前页面展示意图；页面卸载不会释放媒体。摄像头使用通话 Service 持有的唯一原生窗口，不再挂载 React 页面预览或切换 surface。返回地址由 Host 提供，Feature 不执行 App 路由。

用户文本和 TTS 按句事件在 Repository 提交后发布内部事实，媒体状态立即追加字幕，不等待整轮 AI 回复或轮询。歌词流只从这些正式事件生成 AI 行，保留历史句、贴底跟随与翻历史时停止跟随。

实时回复每轮固定角色 TTS 模型，并使用 Speech 的厂商文本契约生成提示词、验证流式句子。合成输入保留当前模型允许的声音和停顿标记；通话记录、播放事件与字幕使用无标记的转写。分句不切断跨 delta 标记；句间显式停顿与两侧正文保留在同一合成单元。模型配置变化只影响下一轮，播放队列不再次解析或验证句子。具体支持范围与邀请开场白的纯正文边界见 [Speech README](../speech/README.md)。

通话小窗使用 112×150 的竖向比例。开启摄像头后，通话页、其他页面和 App 后台保留同一个窗口、位置与预览；关闭摄像头时，后台小窗在同一区域显示 AI 头像并以黑色补足空白。单击没有动作，完整双击松手后返回通话页；整块画面超过系统触摸移动阈值立即拖动，不等待长按，也不同时触发双击。窗口坐标使用完整屏幕范围，不裁状态栏、挖孔或键盘区域。摄像头权限之外需要悬浮显示权限；镜头翻转在通话页控制区操作，挂断仍可从通话页或持续通知直接执行。

头像由宿主从 AI 资料传给原生服务，只读取一次并共享给小窗与持续通话通知，独立的全屏通话背景仍由 Calls 设置管理。用户挂断后的 AI 跟进仍严格解析 JSON；不合法输出报告失败且不交付为聊天消息，不影响已经提交的通话终态与资源释放。

当前实现、验证证据与设备验收清单见 [原生持续通话实施清单](../../../docs/ai-video-call/native-call-implementation-checklist.md)。
